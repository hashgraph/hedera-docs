## Overview

{/* Cover:
    - The problem: audit logs in a database can be edited, reordered or truncated by whoever runs the database; regulators get exports after the fact and must trust them.
    - Why HCS: every message gets a consensus timestamp, a sequence number and a running hash from the network; a topic with a submit key accepts messages only from authorised publishers; anyone can read it through the public mirror node.
    - Differentiator (Luke): a native service at a fixed, low per-message fee; no other network publishes a regulator- or auditor-feed guide.
    - Shared plumbing: the other Finance Workflows templates (DvP, bond, coupons, court-order freeze) can log their lifecycle events here. */}

The workflow has three actors:

* **Issuer**: the operator account the app runs with. Creates the security token and the audit topic, performs the token actions, and publishes an audit entry for each one
* **Compliance officer** (optional): a HashPack account the Issuer authorises as a publisher. Signs and submits the audit entries instead of the Issuer
* **Regulator**: reads the trail through the mirror node. Holds no keys and needs no account

The lifecycle:

1. The Issuer creates the audit topic with a submit key, and a security token with KYC and freeze keys
2. The Issuer performs token actions: issue, grant KYC, transfer, freeze, unfreeze
3. Each action is logged as an audit entry carrying the action's transaction id and the hash of the previous entry
4. The Regulator's feed reads the topic from the mirror node and verifies it: no sequence gaps, an unbroken hash chain, every referenced transaction real and successful
5. Anyone else who tries to publish is rejected by the network

```text
Issuer / Compliance officer          Hedera network                     Regulator (mirror node only)
        |                                  |                                       |
        |-- TokenGrantKyc ---------------->|  txId                                 |
        |-- TopicMessageSubmit(            |                                       |
        |     event, txId, prevHash) ----->|  seq N, consensus time, running hash  |
        |                                  |<-------- GET /topics/{id}/messages ---|
        |                                  |          verify: seq, hash chain, txId|
Outsider -- TopicMessageSubmit ----------->|  INVALID_SIGNATURE (rejected)         |
```

| Component | Technology |
| - | - |
| Audit log | HCS topic with an admin key and a submit key (1-of-n key list: Issuer plus authorised publishers) |
| Logged actions | HTS token create, KYC grant, transfer, freeze, unfreeze |
| Entry format | JSON: event, token, account, amount, transaction id, previous entry hash |
| Regulator feed | Mirror node REST (`/api/v1/topics/{id}/messages`), polled live, verified in the browser |
| Signing | Issuer server-side via `@hiero-ledger/sdk`; compliance officer via HashPack and `@hashgraph/hedera-wallet-connect` |
| Network | Hedera testnet |
