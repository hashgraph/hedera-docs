The Hedera Account Service (HAS) system contract gives smart contracts access to Hedera account features: signature verification against an account's keys ([HIP-632](https://hips.hedera.com/hip/hip-632)), HBAR allowances ([HIP-906](https://hips.hedera.com/hip/hip-906)), and conversion between an account's EVM addresses.

| | |
| --- | --- |
| **Address** | `0x000000000000000000000000000000000000016a` (`address(0x16a)`) |
| **Interface** | [`IHederaAccountService.sol`](https://github.com/hiero-ledger/hiero-contracts/blob/main/contracts/account-service/IHederaAccountService.sol) in hiero-contracts |

## Functions

| Function | Returns | Selector | Description |
| --- | --- | --- | --- |
| `isAuthorizedRaw(address,bytes,bytes)` | `bool authorized` | `0xb2a31da4` | Verifies one ECDSA or ED25519 signature over a 32-byte Keccak-256 hash against the account's key. |
| `isAuthorized(address,bytes,bytes)` | `(int64 responseCode, bool authorized)` | `0xb2526367` | Verifies a protobuf `SignatureMap` over a message against the account's full key, including key lists and threshold keys. |
| `hbarAllowance(address,address)` | `(int64 responseCode, int256 amount)` | `0xfec46666` | Returns the HBAR allowance, in tinybars, that `owner` granted to `spender`. |
| `hbarApprove(address,address,int256)` | `int64 responseCode` | `0xa0918464` | Sets the HBAR allowance, in tinybars, that `owner` grants to `spender`. Calling it again overwrites the previous amount. |
| `getEvmAddressAlias(address)` | `(int64 responseCode, address)` | `0xdea3d081` | Returns the EVM Address from Public Key for an account referenced by its EVM Address from Account ID. |
| `getHederaAccountNumAlias(address)` | `(int64 responseCode, address)` | `0xbbf12d2e` | Returns the EVM Address from Account ID for an account referenced by its EVM Address from Public Key. |
| `isValidAlias(address)` | `bool` | `0x308ef301` | Returns `true` if the address is an EVM Address from Account ID or an EVM Address from Public Key of an existing account. |

A `responseCode` of `22` means `SUCCESS`. See [`HederaResponseCodes.sol`](https://github.com/hiero-ledger/hiero-contracts/blob/main/contracts/common/HederaResponseCodes.sol) for the other values.

<Warning>
On the network, `isValidAlias` returns a single `bool`. The `IHederaAccountService.sol` interface in hiero-contracts declares it as returning `(int64, bool)`, so a call made through that interface fails to decode. Declare `isValidAlias(address) returns (bool)` in your own interface instead.
</Warning>

An account can also call `hbarAllowance(address spender)` and `hbarApprove(address spender, int256 amount)` on its own address to manage its own allowances ([`IHRC906AccountFacade.sol`](https://github.com/hiero-ledger/hiero-contracts/blob/main/contracts/account-service/IHRC906AccountFacade.sol)).

## Verify signatures from Solidity

### ECDSA accounts: `ecrecover`

`ecrecover` works on Hedera as it does on Ethereum. For an account whose EVM address is its **EVM Address from Public Key** (`Keccak-256` of its ECDSA public key), call `ecrecover(hash, v, r, s)`. If the recovered address equals the account's EVM address, the signer controls the account. No Hedera-specific integration is needed.

`ecrecover` cannot verify ED25519 signatures, accounts with key lists or threshold keys, or accounts referenced only by their EVM Address from Account ID (the long-zero form). Use the HIP-632 functions below for those.

### `isAuthorizedRaw`

`isAuthorizedRaw(address account, bytes messageHash, bytes signature) returns (bool)` checks one signature against an account with a single key. It works like `ecrecover`, but supports both ECDSA (secp256k1) and ED25519 keys.

| Parameter | Description |
| --- | --- |
| `account` | The account to check. For an ECDSA signature, this must be the account's EVM Address from Public Key; an EVM Address from Account ID (long-zero) reverts with `INVALID_ACCOUNT_ID`. |
| `messageHash` | The 32-byte Keccak-256 hash that was signed. For ED25519 keys, the signature must be over these 32 bytes. |
| `signature` | The raw signature. The length selects the key type: 64 bytes is ED25519; 65 to 72 bytes (`r`, `s`, then a 1 to 8 byte `v`) is ECDSA. |

* Returns `true` only if the signature is valid for the account's key. A well-formed signature from the wrong key returns `false`; the call itself still succeeds.
* Reverts if the signature length matches neither key type, if an ECDSA `messageHash` is not 32 bytes, if the account does not exist, or if an ED25519 account's key is not a single ED25519 key.

### `isAuthorized`

`isAuthorized(address account, bytes message, bytes signatureMap) returns (int64, bool)` checks signatures against the account's full key, so it supports key lists, threshold keys, and mixed ECDSA and ED25519 keys.

| Parameter | Description |
| --- | --- |
| `account` | The account to check, referenced by its EVM Address from Account ID or its EVM Address from Public Key. |
| `message` | The message bytes. The network hashes the message with Keccak-256 before checking ECDSA signatures; ED25519 signatures must be over the message bytes as given. |
| `signatureMap` | A serialized protobuf [`SignatureMap`](/reference/protobuf/basic-types/signaturemap) with one signature pair per key. |

* Returns `(responseCode, authorized)`. `authorized` is `true` only if the signatures satisfy the account's key.
* Does not revert for a missing account, an account without a key, or a malformed `SignatureMap`. It returns a non-`SUCCESS` response code with `authorized` set to `false`.

### Check the result, not the call

Both functions report an invalid signature through their return values. If you call them with a low-level `call` and only check the call's `success` flag, every well-formed signature passes, including forged ones. Call them through a typed interface and check the returned values:

<Tip>
```solidity
// SPDX-License-Identifier: Apache-2.0
pragma solidity ^0.8.24;

interface IHederaAccountService {
    function isAuthorizedRaw(address account, bytes memory messageHash, bytes memory signature)
        external
        returns (bool authorized);

    function isAuthorized(address account, bytes memory message, bytes memory signature)
        external
        returns (int64 responseCode, bool authorized);
}

contract SignatureChecks {
    IHederaAccountService internal constant HAS = IHederaAccountService(address(0x16a));
    int64 internal constant SUCCESS = 22;

    // Verifies one ECDSA or ED25519 signature over a 32-byte Keccak-256 hash
    function verifySignature(address account, bytes32 messageHash, bytes calldata signature)
        external
        returns (bool)
    {
        return HAS.isAuthorizedRaw(account, abi.encodePacked(messageHash), signature);
    }

    // Verifies a protobuf SignatureMap against the account's full key (key lists and threshold keys included)
    function verifyAccount(address account, bytes calldata message, bytes calldata signatureMap)
        external
        returns (bool)
    {
        (int64 responseCode, bool authorized) = HAS.isAuthorized(account, message, signatureMap);
        return responseCode == SUCCESS && authorized;
    }
}
```
</Tip>

### Gas

`isAuthorizedRaw` charges the `ecrecover` gas cost for an ECDSA signature and a fixed ED25519 verification cost for an ED25519 signature. `isAuthorized` charges based on the keys in the account's key structure, with the ED25519 verification cost for each ED25519 key, so accounts with larger key lists cost more to check.
