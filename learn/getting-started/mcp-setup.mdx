## What Is the Hedera Docs MCP Server?

The [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) is an open standard that creates direct connections between AI applications and external data sources. Instead of relying on general web search results, MCP lets AI tools search your documentation directly for more accurate, up-to-date information.

Hedera's MCP server gives any MCP-compatible AI application access to every page in the Hedera docs navigation, including:

- API references and SDK documentation
- Code examples and tutorials
- How-to guides and quickstarts
- Network concepts and architecture docs
- The OpenAPI specs for the mirror node REST API, the smart contract verification API, and the Hedera status API

### Available Tools

The server exposes three tools:

| Tool | What it does | Read-only |
| :--- | :--- | :--- |
| `search_hedera` | Searches the documentation and returns matching snippets with page titles and links. Use it for broad or conceptual questions. | Yes |
| `query_docs_filesystem_hedera` | Runs read-only shell-style commands (`rg`, `grep`, `find`, `tree`, `ls`, `cat`, `head`, `jq`, and more) against a sandboxed, in-memory copy of the docs pages and the OpenAPI specs. Use it to read a full page, read several pages in one call, run exact keyword or regex searches, or explore the docs structure. | Yes |
| `submit_feedback` | Sends a report about an incorrect, outdated, confusing, or incomplete page to the Hedera docs team. Takes the page path and a description of the problem. | No |

The filesystem tool is how an AI tool reads a complete page. Every page at the URL path `/some/page` is available at `/some/page.mdx`, and the OpenAPI specs are mounted under `/openapi/` (`openapi.yaml`, `hedera-status-api.yaml`, and `smart-contract-verification-api.yaml`). The specs are stored as single-line JSON despite the `.yaml` name, so query them with `jq` rather than `head`. For example, an agent can call it with:

```bash
head -200 /learn/getting-started/mcp-setup.mdx
rg -il "MirrorNodeTokenBalanceQuery" /native
jq -r '.info.title, (.paths | keys[])' /openapi/openapi.yaml
```

Each filesystem call is stateless: the working directory resets to `/` and nothing carries over between calls. Output is truncated to 30 KB per call.

`search_hedera` and `query_docs_filesystem_hedera` only read published documentation. Both carry the MCP annotations `readOnlyHint: true` and `destructiveHint: false`, which some AI tools use to run them without asking for approval. `submit_feedback` is the one tool that sends data: when an AI tool calls it, the page path and feedback text are recorded as page feedback in the Hedera docs team's Mintlify analytics dashboard.

The server also publishes a `hedera` skill as an MCP resource. MCP gives an agent access to the docs content, and the skill tells it how to use that content, so connecting the server gives agents both.

Search and the filesystem cover the pages in the docs navigation. Pages hidden from the navigation are not included.

<Info>
Tool names are specific to each Mintlify-hosted server. Use the names your AI tool reports from the server rather than hardcoding them.
</Info>

### MCP Server URL

```
https://docs.hedera.com/mcp
```

Use this URL to connect any supported AI tool to the Hedera documentation.

### Why MCP Over Web Search?

| Feature | Web Search | MCP |
| :--- | :--- | :--- |
| **Source** | Search engine index (may be stale or incomplete) | The current indexed Hedera docs, searched directly |
| **Noise** | Affected by SEO and ranking algorithms | Goes straight to official docs |
| **Integration** | Separate step from response generation | Searches during response generation |
| **Accuracy** | May surface outdated or third-party content | Answers come from the official docs rather than training data or third-party pages |

## Installation

The Hedera Docs MCP server is a remote `HTTP` server hosted by Mintlify. No code is downloaded or executed on your machine. Your AI tool connects directly to https://docs.hedera.com/mcp over `HTTPS` and reads the documentation through the [tools listed above](#available-tools). The server requires no authentication, wallet, or keys.

To connect, you manually add the server URL to your AI tool's configuration using the setup instructions below. This is the recommended approach because it gives you full visibility into what's being configured, and no third-party packages are installed or executed on your system.

### Quick Connect From Any Docs Page

The contextual menu at the top of every page on docs.hedera.com includes these options:

| Option | What it does |
| :--- | :--- |
| **Copy MCP server URL** | Copies `https://docs.hedera.com/mcp` to your clipboard. |
| **Connect to Cursor** | Installs the Hedera Docs MCP server in Cursor. |
| **Connect to VS Code** | Installs the Hedera Docs MCP server in VS Code. |

### VS Code (GitHub Copilot)

VS Code connects to MCP servers through GitHub Copilot. Add the Hedera server to your Copilot Global configuration so it's available in every workspace.

**Option A: Command Palette (Recommended)**

<VSCodeSetup />

**Option B: Manual Configuration**

Create or edit `~/.copilot/mcp-config.json` (or `$COPILOT_HOME/mcp-config.json` if you set `COPILOT_HOME`) and add the following, then run the verify step above:

```json
{
  "mcpServers": {
    "hedera-docs": {
      "type": "http",
      "url": "https://docs.hedera.com/mcp"
    }
  }
}
```

> **Note:** Earlier versions of this guide used `.vscode/mcp.json` with a `"servers"` key. VS Code still reads that file for compatibility but labels it deprecated, and it only applies to one project. To move an existing entry, copy it into `mcp-config.json` under `"mcpServers"`, then remove it from `.vscode/mcp.json`.

### Devin Desktop

Devin Desktop, formerly Windsurf, connects to MCP servers through its Devin Local agent. Devin Local supports the `stdio`, `Streamable HTTP`, and `SSE` transport types.

1. Open or create the MCP config file for the scope you want:
   - **User** (all your projects): `~/.config/devin/mcp_config.json` (`%APPDATA%\devin\mcp_config.json` on Windows)
   - **Project** (shared through version control): `.devin/mcp_config.json`
2. Add the following:

```json
{
  "mcpServers": {
    "hedera-docs": {
      "url": "https://docs.hedera.com/mcp",
      "transport": "http"
    }
  }
}
```

3. In the Agents window, click **Customize** in the agent sidebar, then click **MCPs**. `hedera-docs` appears in the **This computer** list. Refresh the list if it doesn't.

If you also use Devin CLI, this command adds the server to the same user config file:

```bash
devin mcp add -s user hedera-docs https://docs.hedera.com/mcp
```

> **Note:** The **Available** list on the **MCPs** tab shows servers from your MCP registries. Add the Hedera docs server through the config file rather than installing a similarly named third-party server from that list.

### Gemini CLI

Google's Gemini CLI supports MCP servers through a `settings.json` configuration file. It supports `stdio`, `SSE`, and `Streamable HTTP` transports.

> **Prerequisite:** Install Gemini CLI with `npm install -g @google/gemini-cli@latest`.

<GeminiCliSetup />

To edit the settings file directly instead, add the following to `~/.gemini/settings.json`. In Gemini CLI v0.21.0 and later, the command above writes the same entry:

```json
{
  "mcpServers": {
    "hedera-docs": {
      "url": "https://docs.hedera.com/mcp",
      "type": "http"
    }
  }
}
```

`"type": "http"` selects the Streamable HTTP transport, which the Hedera docs server uses; it does not accept SSE connections. These settings need Gemini CLI v0.21.0 or later. Earlier versions treat `url` as an SSE endpoint and cannot connect, so use `"httpUrl": "https://docs.hedera.com/mcp"` instead (current versions still accept `httpUrl` but mark it deprecated).

## Example Requests

After you connect the server, try these requests. Each one uses a different [Hedera Docs tool](#available-tools).

| Try asking | Tool it uses | What it shows |
| :--- | :--- | :--- |
| *"What replaced `AccountBalanceQuery`? Check the Hedera docs before answering."* | `search_hedera` | An agent answering from memory may still suggest `AccountBalanceQuery`, which no longer works. The docs name its replacement, `MirrorNodeAccountBalanceQuery`. |
| *"Read the Hedera mirror node OpenAPI spec and find the endpoint that lists the tokens an account holds."* | `query_docs_filesystem_hedera` | The agent reads the spec with `jq` instead of guessing the path. It should find `/api/v1/accounts/{idOrAliasOrEvmAddress}/tokens`. |
| *"The example on this Hedera docs page doesn't work with the current SDK: [page URL]. Check the page, and if it's wrong, draft a report for the docs team and show it to me before sending."* | `submit_feedback` | The agent drafts a report with the page path and the problem. After you approve it, the agent sends it to the Hedera docs team. |

## Using Multiple MCP Servers

You can connect the Hedera Docs MCP server alongside other documentation MCP servers. Here's an example Cursor configuration with multiple servers:

```json
{
  "mcpServers": {
    "hedera-docs": {
      "url": "https://docs.hedera.com/mcp"
    },
    "another-docs": {
      "url": "https://example.com/docs/mcp"
    }
  }
}
```

Connected MCP servers do not add documentation content to the conversation until the AI calls a tool. The AI decides when to search based on query relevance, so it doesn't search every connected server for every question. When it does search, each query returns multiple results, so searching several servers for one question can make the conversation much longer and leave less room for the response.

**Best practices for multiple servers:**

- Connect only the servers relevant to your current work.
- Be specific in your prompts so the AI searches the most relevant server.
- Disconnect servers you're not actively using to reduce context usage.

## Troubleshooting

**Server not connecting?**
- Verify the URL is exactly `https://docs.hedera.com/mcp` (no trailing slash).
- Ensure you have an active internet connection.
- Restart your AI tool after adding the configuration.

**Tools not appearing?**
- The server exposes three tools: `search_hedera`, `query_docs_filesystem_hedera`, and `submit_feedback`. If none appear, the connection failed.
- In Cursor, click the refresh button next to the server entry.
- In VS Code, run **MCP: List Servers** from the Command Palette, select `hedera-docs`, and choose **Restart Server**. If that action isn't offered, choose **Stop Server**, then **Start Server**.
- In Claude Code, run `claude mcp list` to verify the server is registered.
- In Devin Desktop, open **Customize** → **MCPs** and check that `hedera-docs` is in the **This computer** list.

**Search returning no results?**
- Try rephrasing your query with more specific Hedera terminology.
- Ensure the MCP server is enabled/active for your current chat session.

**Rate limits:**
Mintlify, which hosts the server, applies rate limits to protect availability:

| Scope | Limit |
| :--- | :--- |
| Per user (IP address) | 5,000 requests per hour |
| `search_hedera` calls across all users of docs.hedera.com | 10,000 requests per hour |
| `query_docs_filesystem_hedera` calls across all users of docs.hedera.com | 10,000 requests per hour |

If a limit is exceeded, the server returns HTTP `429 Too Many Requests`. Back off and retry after a short delay. Limits reset on a rolling hourly window. Mintlify sets these limits and can change them; see [Mintlify's rate limits](https://www.mintlify.com/docs/ai/model-context-protocol#rate-limits) for the current values.
